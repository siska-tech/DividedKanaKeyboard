# A. 薙刀式シフト体系 詳細設計

## A.1 現モデルの限界と新モデルの方針

現 `engine.rs` は「窓内の sc 集合 → flat な single/combo 照合」。これでは薙刀式の以下が表現できない：

- **連続シフト**: シフトキーを押し続ける間、**後続の複数キー**すべてにシフトが掛かる（窓を跨ぐ持続状態）。
- **後置シフト**: ベースキーを先、シフトを後に押す**順序依存**。
- **二重シフト**: シフト2種の同時適用。

→ **レイヤモデル**へ拡張する。薙刀式の元定義 `.txt` 自体が
`({シフト}[ 位置→かな ]` という「**シフト集合をトリガとする面**」の構造をしているため、これに忠実：

```
出力 = LAYER[ 現在アクティブなシフト集合 ][ ベースキー sc ]
```

単打・センターシフト・濁音・拗音・外来音は**すべてこの1モデルに統一**される
（トリガ集合の要素数 0〜2 で表現）。

## A.2 キー役割モデル

各 sc は「ベース面（かな）」を必ず持ち、加えて一部は**シフト能力**を持つ二面性キー。

| 役割         | 定義                                                           | 例（.txt option-input より）                                    |
| ------------ | -------------------------------------------------------------- | --------------------------------------------------------------- |
| `Base`       | 単打でかなを出す                                               | 大半のキー                                                      |
| `Shift(bit)` | 他キーと併用時にシフトとして働く。**単打時は自分のベースかな** | space, 右親(0x24), 左親(0x21), 右中(0x32), 左中(0x2F), あ(0x10) |

シフトビット割当（`ShiftMask: u8`、最大8種）:

| bit | 名称    | sc          | 用途（薙刀式）      |
| --- | ------- | ----------- | ------------------- |
| 0   | CENTER  | 0x2C(space) | センターシフト      |
| 1   | R_THUMB | 0x24        | 濁音等（右親）      |
| 2   | L_THUMB | 0x21        | 濁音等（左親）      |
| 3   | R_MID   | 0x32        | 拗音/外来音（右中） |
| 4   | L_MID   | 0x2F        | 濁音（逆手・左中）  |
| 5   | A_KEY   | 0x10        | 外来音等（あ）      |

> 正確なビット⇔機能対応は `.txt` 転記時に確定（B章）。本書はビット枠だけ定義。

## A.3 シフトキーの tap/hold 曖昧性解決

シフト能力キーは「単打かな」か「シフト」かを実行時に判定する（ホームロウMod同型）。

```
shift_key 押下 → 状態 Ambiguous（保留）
  ├─ tap_window(=既定40ms) 内に “単独で” 解放      → Base 確定（自分のかなを出力）
  ├─ 押下中に他キーが押された                      → Shift 確定（held_shifts へ commit）
  └─ tap_window 経過しても保持中                    → Shift 確定（連続シフト開始）
```

- `tap_window` は判定窓と同一既定値（40ms, 実機調整）。
- Shift確定後、そのキーが解放されるまで `held_shifts` に残る → **連続シフト**が自然に成立。

## A.4 状態（engine v2）

```rust
struct Engine {
    window_ms: u32,
    tap_ms: u32,
    held:        Set<sc>,                 // 物理的に押下中
    held_shifts: ShiftMask,               // Shift確定済みの集合（持続）
    ambiguous:   Vec<(sc, t)>,            // 役割未確定のシフト能力キー
    pending_base: Option<(sc, t)>,        // 後置シフト待ちのベース（A.6）
    last_emit_t: u32,
}
```

## A.5 解決アルゴリズム（レイヤ × ベース → 出力）

ベースキー `b` を解決する瞬間の手順：

```
fn resolve_base(b, shifts: ShiftMask) -> Action:
    # 1) 厳密一致レイヤ: (shifts, b)
    if let Some(a) = LAYERS[shifts].get(b): return a
    # 2) フォールバック: 単打面
    if let Some(a) = LAYERS[0].get(b):      return a
    # 3) 未定義
    return Action::None
```

- `LAYERS[mask]` は `phf::Map<u8, Action>`（base sc → Action）。`mask` ごとに1表。
- **逆順/順不同**はトリガ集合 `shifts` がビットORで可換なので自然成立。

## A.6 後置シフトの扱い（順序依存）

「ベース→シフト」の順で来た場合に、確定前のベースへ遡及適用する：

```
press(base b):
    if 既存 held_shifts あり: 即 resolve_base(b, held_shifts) を出力
    else: pending_base = (b, now)         # シフトが後から来るかもしれない → 保留

press(shift s within window of pending_base):
    held_shifts |= s.bit
    if pending_base=(b,_): 出力 resolve_base(b, held_shifts); pending_base=None

# 保留のまま窓超過 / 次キー / b解放 → pending_base を単打として確定（flush）
tick / release: pending_base 窓超過なら resolve_base(b, held_shifts) で確定
```

- 保留は**最大1キー**・**窓内**のみ（タイプ遅延を最小化）。
- これにより「が（か→濁点後置）」のような後置も拾える。前置（シフト→か）は A.5 で即解決。

## A.7 出力型の拡張

かな以外（IME制御/編集モード/記号直接）を扱うため、戻り値を拡張：

```rust
enum Action {
    Kana(&'static str),         // → romaji → HID（既存経路）
    Keys(&'static [KeyPress]),  // 直接キー列（Enter, IME ON/OFF, ^c 等）
    None,
}
```

- `Kana` は既存 `romaji::kana_to_romaji → hid` をそのまま通す。
- `Keys` は romaji を経由せず直接 HID（編集モードのショートカット、`{vkF2}`=IME ON 等）。
- 編集モード（FR-4.2）は「特定2キー同時で一時レイヤへ入り、続く打鍵を別表で解決」＝ A.5のレイヤ機構の応用で表現する（モードレイヤ）。

## A.8 ワーク例（受入観点）

| 入力（時系列）        | 期待             | 効く機能                    |
| --------------------- | ---------------- | --------------------------- |
| か 単打               | "か"             | 単打 (LAYERS[0])            |
| space+ぬ位置 同時     | センター面のかな | センターシフト              |
| 左中(hold)→し位置     | "じ"（逆手濁音） | 前置シフト                  |
| 左中(hold)→か,さ,た…  | 連続して濁音化   | 連続シフト                  |
| か位置→濁点シフト(後) | "が"             | 後置シフト (A.6)            |
| 右中+左中(hold)→base  | 二重シフト面     | 二重シフト                  |
| 編集2キー同時→hjkl    | カーソル移動     | モードレイヤ + Action::Keys |

# B. 配列データ仕様（レイヤベース）

## B.1 新 YAML スキーマ

`layout/naginata.yaml` を A モデルへ移行：

```yaml
window_ms: 40
tap_ms: 40

# シフト能力キー（A.2）
shifts:
  - { name: CENTER,  sc: 0x2c, bit: 0 }
  - { name: R_THUMB, sc: 0x24, bit: 1 }
  - { name: L_THUMB, sc: 0x21, bit: 2 }
  - { name: R_MID,   sc: 0x32, bit: 3 }
  - { name: L_MID,   sc: 0x2f, bit: 4 }
  - { name: A_KEY,   sc: 0x10, bit: 5 }

# レイヤ: when=トリガのシフト名集合, map= base sc → 出力
layers:
  - when: []                       # 単打面
    kana: { 0x16: "う", 0x18: "し", 0x24: "か", ... }
  - when: [CENTER]                 # センターシフト面
    kana: { 0x10: "あ", ... }
  - when: [L_MID]                  # 逆手濁音面（右手かな→濁音）
    kana: { 0x18: "じ", 0x19: "で", ... }
  - when: [R_THUMB, R_MID]         # 二重シフト/外来音面
    kana: { 0x12: "ふぁ", ... }
    keys: { 0x23: ["LANG1"] }      # Action::Keys 例（IME ON）

matrix_left:  [ {row,col,sc}, ... ]
matrix_right: [ {row,col,sc}, ... ]
```

## B.2 符号化（build.rs codegen）

- `when` のシフト名集合 → `ShiftMask`(u8, bitOR) を**キー**とする。
- 各レイヤ → `phf::Map<u8 base_sc, Action>`。
- レイヤ群 → `phf::Map<u8 mask, &Layer>` または `match mask`。
- `keys` の `"LANG1"` 等の記号は `hid` のシンボル表で `KeyPress` 列へ変換（build時）。

```
LAYERS: phf::Map<u8 /*mask*/, LayerTable>
LayerTable { kana: phf::Map<u8,&str>, keys: phf::Map<u8,&[KeyPress]> }
```

- `pack` は廃止（マスクが順不同を吸収するため不要）。matrix表は現行のまま。

## B.3 .txt からの転記方針

`.txt` の各 `({トリガ}[ … ]` ブロック ⇔ 1レイヤ（when=トリガ）。
将来 build.rs に `.txt`直読コンバータを足せば上流追従（IR-3）。当面は手動でYAML化。

# C. 分割UARTプロトコル 詳細設計

## C.1 物理 / リンク

- UART0: GP0=TX, GP1=RX。**TX/RXコネクタクロス**済（左右同一）。
- ボーレート **921600**（余裕。FR-2.3は115200+）。8N1。
- 1イベント≦2byteのため帯域は十分。レイテンシ目標 ≦2ms（FR-2.2）。

## C.2 フレーム形式

全メッセージは「同期ビット付き先頭1バイト＋従属バイト（同期ビット無し）」で自己同期。

```
KeyEvent (2byte):
  b0: 1 ppp r r r      （最上位=SYNC, p=type=00, ppp予約, rrr=row 0..5）
  b1: 0 c c c c x s s  （c=col 0..13(4bit), s=簡易チェック=b0下位2bitの複製）
Handshake (2byte):
  b0: 1 010 0000       （type=ROLE）
  b1: 0 000 00 mm      （mm: 01=MASTER宣言, 10=SLAVE宣言, 00=PING）
```

- **SYNC**: 先頭バイトのみ bit7=1、従属バイトは bit7=0。受信は bit7=1 を待ってフレーム頭を捕捉。
- **チェック**: `b1` 下位に `b0` の検査ビットを複製し不一致なら破棄（簡易。CRC不要な短さ）。

## C.3 再同期（FR-2.4）

```
受信ループ:
  バイト x 読む
  if x.bit7==1: フレーム頭 → 次バイトを従属として読む → decode
                decode失敗(チェック不一致/従属でbit7=1) → 破棄してフレーム頭探索へ
  else:         同期外れ → 読み捨て（次の bit7=1 まで）
```

- ケーブル抜き差し・ノイズ後は次フレーム頭で自動復帰。状態を持たないので堅牢。

## C.4 役割ネゴシエーション（FR-2.5）

D章の役割判定と連動。UART上の宣言で相互確認：

```
両半身 起動 → role=Undetermined → 周期 PING 送信
USB Configured 検出側 → role=MASTER → MASTER宣言を送信
MASTER宣言 受信側     → role=SLAVE  → 以後 KeyEvent 送信専従
双方Undeterminedが続く（USB未接続）→ TGT: 規定側(例: 右)を暫定MASTER（フォールバック）
USB切断検出 → role=Undetermined へ戻し再ネゴ
```

# D. 役割判定（USB列挙）＋ EE_HANDS 詳細設計

## D.1 役割判定 状態機械

```
        ┌─────────────┐  USB Configured 受信
        │Undetermined │──────────────────────▶ MASTER
        │ (USB試行中)  │  UART:MASTER宣言 受信
        │             │──────────────────────▶ SLAVE
        └──────┬──────┘  T_boot(=500ms)経過 & USB未列挙 & 宣言無
               │                     ▼
               └────────── フォールバック規定（暫定MASTER/SLAVE）

  MASTER ── USB Suspend/切断 ──▶ Undetermined（再ネゴ）
  SLAVE  ── MASTER宣言途絶(タイムアウト) ──▶ Undetermined
```

- 判定の唯一の正は **USBデバイス列挙(Configured)**。VBUS電圧は使わない（§3.1）。
- embassy-usb の `UsbDevice` 状態 / `Handler` の `configured()` で検出。

## D.2 EE_HANDS フラッシュレイアウト

```
2MB Flash 末尾4KBセクタ: 0x101F_F000 〜 0x101F_FFFF
  offset 0: magic[4] = "NGHD"
  offset 4: hand     = 'L' | 'R'
  offset 5..: 0xFF（予約）
```

- 読み: 起動時1回。magic不一致 → 未プロビジョニング扱い → D.4既定。
- 消去単位4KB。書込みは XIP 停止に注意（embassy-rp `flash` のクリティカル区間で実施）。

## D.3 プロビジョニング手順（初回のみ）

2方式を用意：

1. **キー起動方式**（推奨・ツール不要）:
   起動時に特定キーを押下していたら手番書込みモードへ。
   例: 左上キー押しながら起動=この機体を「左」/ 右上キー=「右」として書込み→再起動。
2. **USBシリアル方式**: マスタ時に USB-CDC を開き、ホストから `SET-HAND L` 等を送って書込み。

書込みフロー:
```
sector erase(0x101FF000) → write(magic="NGHD", hand) → reboot
```

## D.4 未プロビジョニング時の既定

- `read_hand()==None` → 暫定 `Left`（PoC）。実運用前に必ずプロビジョニングする運用とする。
- 将来: 予備GPIO(GP22等)のストラップ読みを併用する手も（§2.1）。
