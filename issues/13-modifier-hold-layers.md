# [#13] 修飾キーの長押し保持・モメンタリレイヤ（#12 スコープC）

- **優先度:** P3
- **状態:** 🔲 Todo
- **依存:** #12（PCカスタマイズ: 直接キー層・設定IR・WebHID）
- **関連設計:** 要件 FR-7.1（パラメータ/割当） / 詳細設計 A.7（Action）/ #12 フェーズ3（未使用キー直接割当）

## 目的
#12 フェーズ3 で未使用物理キーを「直接キー／マクロ」に割当できるようにしたが、出力は**タップのみ**
（押下で1ストローク送出、押しっぱなし保持なし）。本 issue は **修飾キーの長押し保持** と
**QMK風のモメンタリレイヤ** を導入し、図のような一般的キーボード運用を可能にする。

理想：
- 物理キーを **Win / Alt / Shift / Ctrl の「修飾キー」** にできる（押している間 modifier を保持＝Alt+クリック等が可能）。
- **Lower / Raise** のような **モメンタリレイヤ**（押している間だけ別レイヤの割当が有効）。
- **mod-tap**（タップ=キー / 長押し=修飾。例 `BS/Shift`: タップBS・長押しShift）。

## スコープ（やること）
- [ ] **保持状態つき HID レポート**：現状は1打=押下/解放の一括ストローク（[main.rs](../firmware/src/main.rs) `send_stroke`/`emit_action`）。
      複数キー/修飾の**同時押し状態**を保持するレポートモデルへ拡張（押下で down、解放で up、現在押下集合を反映）。
- [ ] **修飾キー保持**：直接キー(#12 EXTRA)に「hold」種別を追加。押下で modifier/キーを down、解放で up。
- [ ] **モメンタリレイヤ**：レイヤ番号と「押している間レイヤN」キー。物理(row,col)→レイヤ別割当の解決。
      薙刀式エンジンとの併存方針（レイヤ中は薙刀式をバイパスする等）を決める。
- [ ] **mod-tap / レイヤタップ**：タップ/長押しのしきい値判定（tap_ms 流用）。
- [ ] **設定IR / WebHID 拡張**：hold種別・レイヤ定義の保存と編集UI。

## やらないこと
- 薙刀式の同時打鍵判定そのものの変更（独立に保つ）。
- フル QMK 互換（必要十分なレイヤ/mod-tap に限定）。

## 受入条件（Done の定義）
- [ ] 物理キーを Alt/Shift/Ctrl/GUI の**保持修飾**に割当でき、他キーとの同時押しが効く。
- [ ] Lower/Raise を押している間だけ別レイヤの割当が有効になる。
- [ ] mod-tap（例 タップBS / 長押しShift）が動作する。
- [ ] 既存の薙刀式入力（#03/#04/#10）と #12 のタップ直接キーが回帰しない。

## 実装メモ / 参照
- 現状の出力は `REPORTS` チャネルへ「押下レポート→解放レポート」を即送出（タップ）。
  保持には **現在の押下集合（modifier byte ＋ 最大6キー）を保つ状態**が要り、HID レポート生成を
  ステートフル化する必要がある（[usb_hid.rs](../firmware/src/usb_hid.rs) `report_for`/`release_report` の見直し）。
- #12 の直接キー層 `(hand,row,col)→Action`（[main.rs](../firmware/src/main.rs) `build_direct`/`engine_task`）に
  「hold」種別・レイヤ切替を足す形が素直。設定IR は `OverrideVal` に種別追加 or 新セクションで表現。
- ARMv6-M は RMW アトミック非対応（#12 で確認）。状態は engine_task ローカルで持つのが安全。
